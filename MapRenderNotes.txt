=============GENERATED AREAS PROMPT==============================

I have a Three.js city builder that places buildings, roads, and parks from OSM data. After placement, I need to procedurally populate two types of areas with street furniture. All generated geometry must be collidable via `scene.registerCollidable(mesh)` after `geometry.boundsTree = new MeshBVH(geometry)` is assigned. Grindable elements are additionally passed to `_buildRailMesh()` as synthetic way objects. Non-grindable collidables are registered normally but not passed to `_buildRailMesh`.

Existing context:

* `elev(x, z)` returns terrain Y relative to map centre
* `_snapY(x, z, elev, terrainMesh, bias)` raycasts for exact surface Y
* Buildings use `MeshToonMaterial` with `vertexColors: true`, colours from `buildingPalette(tags)`
* A `structurePalette(tags)` function reads material tags and falls back to `#909090`
* Placed building footprints are available as `placedFootprints` array of `{ verts }` polygon arrays in XZ
* The map is divided into a grid; `radiusMeters` defines the half-extent; `lat`/`lng` are the map centre

Tasks:

1. Write `_findEmptyCells(placedFootprints, roadWays, radiusMeters, cellSize = 40)`. Divide the `radiusMeters × radiusMeters` area into a grid of `cellSize` cells. Mark a cell occupied if any building footprint vertex or road coord falls within it. Return the array of empty cell centres `{ x, z }`.
2. Write `_buildConstructionSite(cx, cz, elev, terrainMesh, seed)`. Given a cell centre and a numeric seed, use a seeded pseudo-random function (LCG or similar, no external lib) to place: 2–4 concrete barrier blocks (box geometry ~2m×0.8m×0.4m, grey, non-grindable collidable), 1–3 scaffolding tube runs (thin box geometry ~4–8m long, 0.1m diameter, at 0.4m and 1.2m height, grindable), and 1 optional tall scaffolding vertical post (non-grindable). All placed relative to `(cx, cz)` with Y from `_snapY`. Return a `THREE.Group`.
3. Write `_buildParkFurniture(parkWay, elev, terrainMesh, seed)`. Given a park polygon way, scatter inside it: bench-style ledges (box geometry ~1.8m×0.45m×0.4m, grindable), low walls (box ~3–6m×0.6m×0.3m, grindable), bollard lines (row of 0.15m diameter × 0.9m cylinders spaced 1.2m apart, non-grindable). Return a `THREE.Group`.
4. Write `_buildSkatepark(cx, cz, angle, elev, terrainMesh, seed)`. Given a centre position, orientation angle, and numeric seed, use the same seeded pseudo-random function to place: a flat concrete pad (earcut-triangulated rectangular polygon at terrain level, toon-material collidable, added to the shared buildings buffer rather than a separate mesh), 1–2 quarter-pipes (parametric swept-arc geometry — a profile of flat base → curved transition → vertical lip extruded along a width, collidable, toon material, concrete grey via `structurePalette`), 1 kicker ramp (two angled quads meeting at a ridge, collidable, same material), and 2–4 grindable rails constructed as synthetic way objects passed to `_buildRailMesh()` (positioned along the pad edges and atop ramp lips). All elements are placed relative to `(cx, cz)` with Y from `_snapY`, and rotated by `angle` around the vertical axis. The method appends solid geometry directly into the caller's `pos/nrm/col/idx` buffer arrays and pushes rail buffers into `allRailBuffers` before `_flushRailMesh` is called, so all skate park geometry shares the single merged collidable mesh with buildings. In `build()`, after `_findEmptyCells` is called, designate a subset of empty cells as skate park locations (e.g. 15% probability, seeded, non-overlapping with construction sites), call `_buildSkatepark` for each, and pass the resulting rail buffers into `allRailBuffers`.
5. In `build()`, after all ways are processed and terrain is built: call `_findEmptyCells` and for each empty cell within `radiusMeters * 0.8`, with 30% probability (seeded by cell position), generate a construction site; for each park/grass way, generate park furniture. Add all groups via `scene.addObject()`.
